DevOps midterm taskPart 1 — Linux administration 
Goal: Manage project files, permissions, processes and system monitoring using Linux commands and Bash scripting.
Task 1.1. Project structure 
Create the following directory structure, replacing the example name with your own.
asan-abai-student-api/
├── scripts/
├── logs/
├── backups/
├── src/
├── Dockerfile
├── docker-compose.yml
├── Jenkinsfile
├── build.gradle
└── README.md
Requirements:
Create all directories using terminal commands.
Create a personal Bash script named Asan_Abai_system_report.sh.
Create an empty log file named Asan_Abai_system_report.log.
Display the directory tree and verify that all required files exist.
Task 1.2. System monitoring script 
Write a Bash script that displays and saves the following information:
Student's full name.
Current date and time.
Current username.
Operating system and kernel version.
CPU and memory information.
Disk usage.
Available disk space.
The output must be saved to the student's personal log file.
Task 1.3. Permissions and backup 
Make the Bash script executable.
Configure permissions so that the owner can read, write and execute the script, while group members and others have read-only access.
Create a backup of README.md in the backups/ directory, including the student's name in the backup filename.
Verify the file permissions using ls -l.
Demonstrate that the backup exists and has the expected contents.
Task 1.4. Process and log analysis 
Display running processes and identify a process related to Java, if one is running.
Display the last five lines of the personal system report log.
Search the log for the student's surname.
Write the results of the search to Asan_Abai_log_analysis.txt.
Explain the difference between > and >> in Linux.
Evidence: Terminal demonstration, script source code, output log, permissions and backup file.
 Part 2 — Git and GitHub 
Goal: Demonstrate an individual Git workflow and maintain the Spring Boot CRUD application in a remote repository.
Task 2.1. Repository initialization 
Initialize a Git repository in the project directory.
Configure your Git username and email.
Create a .gitignore file.
Add the project files and make the first commit:
Initial commit: Asan Abai Student API
The commit message must contain the student's actual name.
Task 2.2. Branching and feature development 
Create a personal feature branch:
feature/asan-abai-crud
On this branch:
Implement or improve one CRUD operation.
Update README.md with your name and a description of the change.
Make at least two meaningful commits.
Merge the branch into main.
Task 2.3. Conflict resolution 
Create a branch named feature/asan-abai-documentation.
Modify the same line in README.md on two different branches.
Merge the branches and resolve the resulting conflict manually.
Commit the resolution.
Show the final Git history.
Task 2.4. Remote repository and version tags 
Create a personal GitHub repository named asan-abai-student-api.
Push the main branch and feature branches.
Create a Git tag named v1.0-asan-abai.
Show the remote URL, commit history, branches and tag.
Explain why .env files, passwords and database credentials must not be committed.
Evidence: GitHub repository, commit history, branch merge, conflict resolution and tag.
 Part 3 — Docker and Docker Compose 
Goal: Containerize the Spring Boot CRUD application and its PostgreSQL database.
Task 3.1. Dockerfile 
Create a multi-stage Dockerfile for the Spring Boot application.
Requirements:
Use an appropriate official JDK image for the build stage.
Build the application using Gradle.
Use a suitable Java runtime image for the final stage.
Copy the generated JAR into the runtime image.
Expose the application's configured port.
Use an individual image name and version tag.
Example:
asan-abai-student-api:v1.0-asan-abai
Build the image and show its size and creation details.
Task 3.2. Docker Compose and PostgreSQL 
Create a docker-compose.yml file containing:
A Spring Boot application service.
A PostgreSQL database service.
Environment variables for database configuration.
A persistent named volume for PostgreSQL data.
A dedicated Docker network.
A health check for PostgreSQL.
Use a personalized Compose project name, such as asan-abai-student-api.
Start the services and verify that both containers are running. Ensure that the application connects to PostgreSQL using the Docker service name rather than localhost.
Task 3.3. Container management 
Perform the following tasks:
List running containers.
Display application container logs.
Inspect the container configuration.
Execute a command inside the application container.
Stop and restart the application service.
Rebuild the image after modifying the application version.
Demonstrate that PostgreSQL records persist after restarting the services.
Task 3.4. Individual API testing 
Using Postman or curl, demonstrate:
Creating a student with your name in the test data.
Retrieving all students.
Retrieving one student by ID.
Updating a student's information.
Deleting a student.
Handling a request for a nonexistent student.
Use your personalized application URL and provide evidence of successful responses.
 Part 4 — Jenkins CI/CD 
Goal: Automate the build and verification of the student's Spring Boot CRUD application.
Task 4.1. Jenkins setup 
Create a Jenkins job named Asan_Abai_Student_API.
Configure the job to use your own GitHub repository.
Configure the required JDK, Gradle wrapper and Docker-capable build agent.
Store any required credentials in Jenkins Credentials.
Verify that Jenkins can check out the source code.
Task 4.2. Personalized Jenkinsfile 
The repository must contain a standard file named Jenkinsfile.
Create pipeline stages for:
Checkout — retrieve source code from GitHub.
Build — compile the Spring Boot application using Gradle.
Test — execute automated tests.
Docker Build — build the personalized Docker image.
Verify — check that the image exists and report the result.
The pipeline must use the student's actual Docker image name and must stop when the build or tests fail.
Example personalized image reference:
asan-abai-student-api:v1.0-asan-abai
The student's name should also appear in the build log.
Task 4.3. Pipeline execution and troubleshooting 
Run the pipeline successfully.
Introduce a controlled error in a test or build configuration.
Demonstrate the failed pipeline.
Fix the error and rerun the pipeline.
Explain the failure and show the successful result.
Do not introduce an error into the shared production environment; use your own test branch.
Task 4.4. Automation 
Configure a GitHub webhook or a polling trigger.
Make a new commit in your repository.
Demonstrate that the pipeline starts automatically.
Show the build history and console output.
Explain the difference between Continuous Integration and Continuous Deployment.
Important: Automated deployment is not required for this part unless the instructor explicitly enables it. If deployment is implemented, use an authorized deployment host and appropriately secured credentials.
